## 1. 개요

### 1.1 서비스 정의
반려동물 보호자가 **이상 증상을 자연어로 설명**하면, **3개의 LLM(GPT, Gemini, Claude)이 동시에 판단**하고 그 결과를 통합하여 **위험도 점수(1.0–10.0)와 행동 가이드**를 제공하는 웹 기반 트리아지 서비스.

### 1.2 핵심 사용자 흐름
```
[F1] 펫 정보 등록·확인          (효지)
        ↓
[F2] 증상 대화형 입력 + 3개 LLM 병렬 호출  (은지)
        ↓
[F3] 3개 LLM 응답 통합 → 진단명 + 위험도 산정  (연수)
        ↓
   ┌─── 위험도 분기 ───┐
   ↓                   ↓
1–4점                5–10점
[F4] 홈케어 가이드   [F5] 병원 지도 + 의사용 차트
 (재원)               (선인)

※ 진단 결과가 부적절하면 [F2]로 복귀 (iteration)
```

### 1.3 플랫폼
- **웹 애플리케이션** (반응형, 모바일 우선)
- 비회원 사용 가능 (펫 정보는 로컬 스토리지 저장)

## 3. 사용자 시나리오

### Story A — 새벽의 구토
> 새벽 2시, 미연 씨의 3살 요크셔테리어 '콩이'가 구토를 했다. 사료가 섞여 있다. 미연 씨는 앱을 열고 "콩이가 토했어, 사료가 그대로 나왔어"라고 적는다. 시스템이 후속 질문을 한 뒤 GPT·Gemini·Claude에 동시에 묻고, **위험도 3.2 / 가벼운 소화불량 의심**을 안내한다. "물을 충분히 주세요"라는 가이드를 받고 안심한다.

### Story B — 노령견의 이상 행동
> 19살 말티즈 '설탕이'를 키우는 정현 씨가 "설탕이가 빙글빙글 돌아"라고 입력한다. 시스템이 노령견의 맥락을 인지하고 위험도 7.8, **전정기관 이상 의심, 즉시 병원 권고**를 안내한다. 지도 버튼을 누르자 24시간 동물병원이 표시된다. 병원 도착 후 의사에게 자동 생성된 차트를 보여준다.

### Story C — 진단이 마음에 안 들 때
> "감기"라는 결과를 받았지만 직감적으로 더 심각해 보인다. "다시 설명할게"를 눌러 추가 증상(피 섞인 토)을 입력하면, 시스템이 위험도를 9.4로 재산정한다.

### F1. 펫 정보 등록
**담당: 효지**

#### 책임
보호자가 반려동물의 신상·생활 정보를 등록·수정하고, 진단 시작 시점에 그 정보를 확인할 수 있게 한다.

#### 입력 필드
| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| 이름 | string | ✓ | |
| 종 | enum | ✓ | 강아지/고양이/기타 |
| 품종 | string | ✓ | 자동완성 추천 |
| 나이 | number | ✓ | 개월 단위까지 |
| 성별 | enum | ✓ | 수컷/암컷 |
| 중성화 여부 | boolean | ✓ | |
| 몸무게(kg) | number | ✓ | |
| 병력 | string[] | | 다중 선택 또는 자유 입력 |
| 상시 복용 약물 | string[] | | |
| 사료 종류 | enum | | 건식/습식/생식/혼합 |
| 자주 먹는 사료 브랜드 | string | | |
| 좋아하는 음식 | string[] | | |
| 알레르기 | string[] | | |

#### 일일 컨디션 입력 (선택)
- 전날 먹은 음식
- 용변 형태: 정상 / 설사 / 변비 / 혈변
- 활동량: 평소대로 / 줄어듦 / 늘어남
- 자유 메모

#### 동작
1. 최초 진입 시 등록 화면 노출.
2. 진단을 시작하기 전, **등록된 정보를 요약 카드로 먼저 보여준다.**
3. 보호자가 카드 위에서 직접 수정 가능.
4. "이 정보로 시작" 버튼 클릭 시 F2로 진입.
5. 다중 펫 등록 가능, 진단 시작 시 어느 펫인지 선택.

#### 산출 인터페이스 (→ F2)
```typescript
interface PetContext {
  pet: Pet;
  dailyLog?: DailyLog;
}
```

#### 완료 기준 (DoD)
- 펫 정보가 로컬 스토리지에 저장된다.
- 새로고침 후에도 등록한 펫이 유지된다.
- 진단 시작 직전에 정보 요약 카드가 모든 등록 필드를 노출한다.

#### 현재 베이스 코드 반영 사항 (효지, 2026-04-29)
- 프론트(`frontend/src/MainPage.js`)에 F1 등록/수정/다중 펫 선택 UI를 추가하고, 저장 데이터는 로컬 스토리지(`pet_health_checker_f1_pets_v1`, `pet_health_checker_f1_daily_logs_v1`)에 보관한다.
- 등록 후 요약 카드에서 `"이 정보로 시작"`으로 F2 진입 전 선택 펫 컨텍스트를 확정한다.
- 백엔드 `models.py`에 `Pet`, `DailyLog`, `PetContext` 타입을 추가하고, `/api/diagnose` 요청에 `pet_context`를 포함할 수 있도록 확장했다.
- 백엔드 `database.py`에 `pets`, `daily_logs` 테이블과 `consultations.pet_id`, `consultations.pet_context_json` 컬럼을 반영해 F1→F2 인터페이스 저장 경로를 준비했다.

### F2. 증상 대화형 입력 + 3개 LLM 병렬 호출
**담당: 은지**

#### 책임
보호자가 반려동물의 증상을 자연어로 설명할 수 있는 채팅 인터페이스를 제공하고, 충분한 정보가 모이면 **GPT·Gemini·Claude 세 개의 LLM에 동시에 동일한 페이로드를 전달**한다. 각 LLM의 raw 응답을 수집하여 F3로 넘긴다.

#### 수신 인터페이스 (← F1)
- `PetContext`

#### 동작 (대화 수집 단계)
1. 화면 상단에 펫 요약 칩 표시 (예: "콩이 · 요크셔테리어 · 3살").
2. 시스템 인사 후 "어떤 증상이 있나요?" 질문.
3. 보호자가 자유 텍스트로 입력.
4. 시스템이 후속 질문으로 정보를 보강:
   - 증상 발생 시점 ("언제부터인가요?")
   - 빈도 ("몇 번이나?")
   - 동반 증상 ("다른 이상한 점은?")
   - 행동 변화 ("평소랑 다른 점은?")
5. 키워드 감지 시 빠른 선택지(quick reply) 제공.
   예: "구토" 입력 → [노란 거품 / 사료 그대로 / 피 섞임 / 잘 모르겠음]
6. 최소 정보(증상 + 시점 + 빈도) 충족 시 "진단 시작" 버튼 활성화.

#### 동작 (LLM 병렬 호출 단계)
"진단 시작" 클릭 시:

1. **세 개의 LLM에 동시에 동일한 페이로드 전달:**
   - **OpenAI GPT** (예: gpt-4o)
   - **Google Gemini** (예: gemini-1.5-pro)
   - **Anthropic Claude** (예: claude-sonnet-4-20250514)

2. 각 LLM에 다음 동일한 시스템 프롬프트와 입력을 전달:
   ```
   [시스템 프롬프트]
   당신은 반려동물의 증상을 분석하는 트리아지 어시스턴트입니다.
   확정 진단을 내리지 마세요. 의심되는 진단명과 위험도(1.0-10.0)만 제시하세요.
   응답은 반드시 지정된 JSON 스키마를 따라야 합니다.

   [입력]
   - 펫 정보: {PetContext}
   - 보호자와의 대화: {messages}
   ```

3. 각 LLM이 다음 JSON 스키마로 응답하도록 강제:
   ```json
   {
     "diagnosis_candidates": [
       { "name": "급성 위염", "confidence": 0.6, "reasoning": "..." }
     ],
     "urgency_score": 6.5,
     "urgency_rationale": "...",
     "red_flags": ["혈변", "12시간 이상 지속 구토"],
     "should_visit_hospital": true
   }
   ```

4. 세 호출은 **병렬(Promise.all)** 로 실행, 전체 타임아웃 15초.
5. 응답 도착 시 로딩 인디케이터에 모델별 상태 표시 ("Claude ✓ / GPT ✓ / Gemini 분석 중…").
6. 한 모델이 실패해도 나머지 모델 결과로 진행 가능 (최소 2개 성공 필요).

#### 반복(Iteration) 처리
- F3 결과 화면에서 "이 진단이 맞지 않아요" 클릭 시 채팅창으로 복귀.
- 이전 대화는 보존하고, 보호자가 추가 정보를 덧붙인다.
- "진단 다시 시작" 클릭 시 누적된 대화 전체를 다시 3개 LLM에 병렬 호출.

#### 산출 인터페이스 (→ F3)
```typescript
interface MultiLLMResponse {
  petContext: PetContext;
  messages: Message[];
  iterationCount: number;
  llmResponses: LLMResponse[]; // 3개 (또는 실패 시 2개)
  totalLatencyMs: number;
}

interface LLMResponse {
  modelName: 'gpt-4o' | 'gemini-1.5-pro' | 'claude-sonnet-4';
  status: 'success' | 'failed' | 'schema_violation';
  rawResponse?: object;
  parsedResponse?: {
    diagnosis_candidates: Diagnosis[];
    urgency_score: number;        // 1.0 - 10.0 (소수점 1자리)
    urgency_rationale: string;
    red_flags: string[];
    should_visit_hospital: boolean;
  };
  latencyMs: number;
  errorMessage?: string;
}
```

#### 완료 기준 (DoD)
- 3개 LLM 병렬 호출이 정상 동작한다.
- 한 모델이 실패해도 나머지 결과로 진행된다.
- 모델별 상태가 사용자에게 시각적으로 보인다.
- 반복 진입 시 이전 대화가 보존되고 다시 3개 LLM 호출이 일어난다.
- 채팅 UI가 모바일에서 정상 동작한다.

### F3. 3개 LLM 응답 통합 + 진단명·위험도 산정
**담당: 연수**

#### 책임
F2에서 받은 **3개 LLM의 출력을 비교·통합**하여 보호자에게 보여줄 **최종 진단명, 위험도(소수점 포함), 병원 방문 권고 여부**를 결정한다.
**F3는 LLM을 직접 호출하지 않는다.** 오직 통합 알고리즘과 결과 표시만 담당한다.

#### 수신 인터페이스 (← F2)
- `MultiLLMResponse` (성공한 LLM 응답 2~3개 포함)

#### 모델별 위험도 표시
세 모델의 위험도를 **개별적으로 모두 노출**한다 (투명성):

```
┌────────────────────────────┐
│  Claude    ▮▮▮▮▮▮▮░░░ 7.0  │
│  GPT-4o    ▮▮▮▮▮▮▮▮░░ 7.5  │
│  Gemini    ▮▮▮▮▮▮▮▮▮░ 8.0  │
└────────────────────────────┘
        통합 위험도: 7.5 / 10
```

#### 통합 알고리즘

**위험도 통합:**
- 기본값: 3개 모델 점수의 **평균** (소수점 첫째자리까지).
- 단, 최댓값과 최솟값이 **3.0점 이상 차이** 나면 **보수적으로 최댓값 채택** (안전 우선).
- 모델이 2개만 성공한 경우: 두 점수의 **평균**, 단 차이가 3.0 이상이면 최댓값.

**진단명 통합:**
- 2개 이상 모델이 동일/유사 진단을 제시 → 합의 진단으로 우선 노출.
- 합의가 없으면 모든 모델의 confidence 최상위 진단을 모두 나열 (예: "Claude는 위염, GPT는 식이불량, Gemini는 이물질 섭취로 봅니다").

**병원 방문 권고:**
- 통합 위험도 ≥ 5.0 → 무조건 권고.
- 통합 위험도 < 5.0이라도 모델 중 하나라도 `should_visit_hospital: true`이면 "권고는 아니지만 가능하면 진료" 문구 추가.

#### 위험 등급 매핑
| 점수 범위 | 등급 | 색상 | 분기 |
|---|---|---|---|
| 1.0–2.9 | 거의 정상 | 초록 | F4 (홈케어) |
| 3.0–4.9 | 가벼운 이상 | 연두 | F4 (홈케어) |
| 5.0–6.9 | 주의 필요 | 노랑 | F5 (병원) |
| 7.0–8.9 | 응급 | 주황 | F5 (병원) |
| 9.0–10.0 | 즉시 응급 | 빨강 | F5 (병원, 24시간 우선) |

#### 출력 화면 구조
- **상단**: 통합 위험도 (큰 숫자 + 색상 + 한 줄 요약 메시지)
  - 예시 메시지: "위험도는 9.6입니다. 급합니다 바로 병원에 가세요!" / "위험도는 1.5예요. 가벼운 체기 같아요"
- **중단**: 모델별 위험도 비교 차트 (위 ASCII 이미지 참고)
- **본문**: 통합 진단명 (합의 / 비합의 케이스별 표시)
- **접힘 영역**: 모델별 raw reasoning ("AI들의 의견 자세히 보기")
- **하단 CTA**:
  - "이 진단이 맞지 않아요" → F2로 복귀
  - 분기 버튼: F4(홈케어) 또는 F5(병원)

#### 산출 인터페이스 (→ F4 또는 F5)
```typescript
interface DiagnosisResult {
  conversationId: string;
  llmResponses: LLMResponse[];           // F2에서 받은 원본 응답들 그대로 전달
  modelScores: { [model: string]: number }; // 모델별 위험도
  consolidatedUrgency: number;           // 1.0 - 10.0
  consolidatedDiagnoses: Diagnosis[];
  consensusType: 'agreed' | 'split';     // 합의 여부
  redFlags: string[];
  shouldVisitHospital: boolean;
  branch: 'homecare' | 'hospital';       // F4 or F5
  headlineMessage: string;               // 한 줄 요약 메시지
  createdAt: string;
}
```

#### 완료 기준 (DoD)
- 모델별 위험도와 통합 위험도가 모두 화면에 명확히 표시된다.
- 위험도가 소수점 첫째자리까지 정확히 노출된다.
- 모델 간 점수 차이가 큰 경우 보수적 통합이 동작한다.
- 합의/비합의 진단이 시각적으로 구분된다.
- "다시 설명할게" 버튼이 F2로 정상 복귀시킨다.

### F4. 홈케어 가이드 (위험도 1–4)
**담당: 재원**

#### 책임
위험도가 낮은 경우, 보호자가 집에서 **해야 할 것 / 하지 말아야 할 것 / 악화 신호**를 명확히 알 수 있도록 행동 가이드를 출력한다.

#### 수신 인터페이스 (← F3)
- `DiagnosisResult` (단, `branch === 'homecare'`인 경우에만 진입)

#### 출력 구조
```
┌─ 지금 해야 할 것 ──────────┐
│ ✓ 미지근한 물을 자주 줍니다  │
│ ✓ 따뜻한 곳에서 쉬게 합니다  │
│ ✓ 12시간 금식 후 소량 급여  │
└────────────────────────┘

┌─ 절대 하지 말 것 ──────────┐
│ ✗ 사람 음식을 주지 마세요   │
│ ✗ 인터넷 민간요법 금지      │
│ ✗ 임의로 약을 먹이지 마세요 │
└────────────────────────┘

┌─ 이런 신호가 보이면 즉시 병원 ─┐
│ • 12시간 이상 지속되는 구토    │
│ • 혈변 또는 혈뇨              │
│ • 의식 저하, 경련             │
└──────────────────────────┘
```

#### 동작
- 별도 LLM 호출로 펫의 종/품종/나이/병력/진단명에 맞춰 가이드를 동적으로 생성.
- 세 섹션(해야 할 것 / 하지 말 것 / 악화 신호)은 **항상 모두 출력**한다.
- 가이드 하단:
  - **"상태가 나빠지면 다시 진단"** → F2로 복귀.
  - **"그래도 병원에 가고 싶어요"** → F5로 강제 진입.

#### 안전 규칙
- 약물 이름·용량은 출력하지 않는다.
- "확실히 ○○병입니다" 같은 단정 표현 금지. "○○ 가능성이 있습니다" 톤 유지.
- 화면 하단에 **"본 가이드는 수의학적 진단을 대체하지 않습니다"** 고정 푸터.

#### 완료 기준 (DoD)
- 세 섹션이 항상 비어있지 않게 채워진다.
- 진단명·펫 정보에 따라 가이드 내용이 달라진다 (하드코딩 금지).
- "다시 진단" 버튼이 F2 채팅 이력을 보존한 채 복귀시킨다.

### F5. 병원 지도 + 의사 전달용 차트 (위험도 5–10)
**담당: 선인**

#### 책임
위험도가 높은 경우, 보호자가 **즉시 인근 병원을 찾고**, 도착 후 **의사에게 보여줄 수 있는 정리된 차트**를 제공한다.

#### 수신 인터페이스 (← F3)
- `DiagnosisResult` (단, `branch === 'hospital'`인 경우에만 진입)

#### F5-A. 병원 지도

**동작**
1. 결과 화면에 "근처 병원 보기" 버튼 노출 (위험도 7.0+면 자동 펼침).
2. 클릭 시 **네이버 지도 API** (Maps JavaScript API + Local Search API) 호출.
3. 브라우저 Geolocation으로 사용자 현재 위치 획득.
4. 반경 5km 내 동물병원 마커 표시.
5. **위험도 7.0 이상이면 24시간 동물병원만 필터링**하여 우선 표시.

**병원 카드 정보**
- 병원 이름
- 거리 (km)
- 전화번호 ("전화 걸기" 버튼)
- 영업시간 (24시간 여부 강조)
- "길찾기 열기" 버튼 (네이버 지도 앱/웹 딥링크)

**폴백**
- 위치 권한 거부 시: 시/구 직접 입력 받아 검색.
- 네이버 API 실패 시: 카카오맵 검색 링크로 폴백.

#### F5-B. 의사 전달용 차트

**동작**
- "의사에게 보여주기" 버튼 클릭 시 전체화면 모드 (밝기 자동 최대).
- 다음 정보를 한 화면 카드 형태로 정리:

```
[펫 기본 정보]
- 이름 / 종·품종 / 나이 / 성별 / 몸무게
- 중성화 여부 / 알레르기 / 상시 복용 약물

[병력]
- (등록된 모든 병력 나열)

[최근 컨디션]
- 전날 식이: ...
- 용변: ...
- 활동량: ...

[현재 증상 (시간순)]
- 02:14 — 구토 1회, 사료 그대로 섞임
- 02:30 — 무기력, 물 거부
- 03:00 — 추가 구토 2회

[AI 트리아지 결과]
- 통합 위험도: 7.5 / 10
- 모델별 위험도: Claude 7.0 / GPT 7.5 / Gemini 8.0
- 의심 진단: 급성 위염 / 이물질 섭취
- Red flags: 혈변 가능성

[보호자 메모]
- (자유 입력 필드)
```

- "이미지로 저장" / "PDF로 저장" 옵션 제공.

#### 안전 규칙
- 위험도 7.0 이상 화면 상단에 **빨간 경고 배너** 강제: "지금 즉시 병원으로 이동하세요".
- 의사용 차트는 **AI 진단을 참고용으로만 명시**.

#### 완료 기준 (DoD)
- 네이버 지도 마커 클릭 시 병원 정보가 카드로 노출된다.
- 위험도 7.0 이상에서 24시간 병원만 우선 표시된다.
- 의사용 차트는 모바일 한 화면에 모든 섹션이 잡힌다.
- 차트의 "이미지로 저장"이 정상 동작한다.

## 7. 비기능 요구사항

### 7.1 응답 속도
- 채팅 후속 질문: 3초 이내.
- F2의 3개 LLM 병렬 호출: **15초 이내**.
- 초과 시 "분석 중" 인디케이터 + 도착한 모델부터 부분 결과 노출.

### 7.2 안전성
- 모든 화면 푸터: **"본 서비스는 수의학적 진단을 대체하지 않습니다"**
- 위험도 7.0 이상 화면: 빨간 경고 배너 강제.
- 약물 이름·용량은 어떤 화면에서도 출력하지 않음.

### 7.3 접근성
- WCAG 2.1 AA.
- 위험 등급은 색상 + 아이콘 + 텍스트 병행 (색맹 사용자 대응).

### 7.4 개인정보
- 펫 정보는 로컬 스토리지에만 저장.
- LLM 호출 시 펫 이름 가명 처리 옵션 제공.
